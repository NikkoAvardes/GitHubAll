# Workout Tracker

Мобильное приложение для планирования и учета силовых тренировок. Пользователь
создает аккаунт, выбирает упражнения, собирает программы тренировок, фиксирует
вес и количество повторений, а затем просматривает статистику и историю занятий.

Клиент поддерживает запуск на **iOS**, **Android** и **Web** благодаря Expo и
React Native.

> В этом репозитории находится только frontend. Для полноценной работы нужен
> запущенный backend с REST API, описанным ниже.

## Возможности

- регистрация и вход по email, имени пользователя и паролю;
- сохранение авторизации между запусками приложения;
- каталог упражнений с фильтрацией по группам мышц;
- создание персональных программ:
  - название программы;
  - список упражнений;
  - целевое количество подходов;
- запуск одной активной тренировки;
- таймер продолжительности тренировки;
- добавление и удаление подходов с указанием веса и повторений;
- подсказка с результатом предыдущего подхода для того же упражнения;
- завершение тренировки;
- статистика:
  - количество тренировок;
  - количество подходов;
  - общий поднятый вес;
- история завершенных тренировок;
- поиск других пользователей и отправка заявок в друзья;
- принятие входящих заявок в друзья.

## Как работает приложение

### 1. Запуск и проверка сессии

Корневой layout вызывает `checkAuth()` при старте. Приложение читает из
AsyncStorage значения `token` и `user`:

- если оба значения есть, пользователь сразу попадает в основную часть
  приложения;
- если данных нет, отображается приветственный экран;
- пока проверка выполняется, показывается индикатор загрузки.

### 2. Авторизация

При регистрации или входе клиент отправляет данные на backend. В ответе
ожидаются `access_token` и объект `user`. Оба значения сохраняются локально.

Axios-интерсептор автоматически добавляет токен в каждый запрос:

```http
Authorization: Bearer <token>
```

Если backend отвечает `401`, токен и сохраненный пользователь удаляются.

### 3. Создание программы

1. Пользователь открывает раздел **Программы**.
2. Нажимает кнопку добавления.
3. Вводит название программы.
4. Выбирает упражнения из каталога.
5. Для каждого выбранного упражнения задает целевое число подходов.
6. Клиент отправляет программу на backend и обновляет список программ.

### 4. Проведение тренировки

1. Пользователь запускает программу с главного экрана или из раздела
   **Программы**.
2. Backend создает активную сессию.
3. На экране тренировки запускается таймер.
4. Для упражнения пользователь вводит вес и повторения.
5. Подход отправляется на backend и появляется на экране.
6. Последний результат по упражнению подставляется в форму как подсказка.
7. После нажатия **Готово** сессия завершается и появляется в истории.

Одновременно предполагается только одна активная тренировка. Если пользователь
пытается начать вторую, приложение предлагает продолжить уже существующую.

### 5. Профиль и социальные функции

Профиль загружает статистику и историю тренировок. Поиск пользователей начинает
выполняться после ввода более двух символов. Для найденного пользователя можно
отправить заявку в друзья, а входящую заявку — принять.

## Установка

```bash
git clone <URL-репозитория>
cd WorkoutTracker
npm install
```

Создайте файл `.env` в корне проекта:

```env
EXPO_PUBLIC_BACKEND_URL=http://localhost:8000
```

Переменная используется как базовый адрес backend. Клиент автоматически
добавляет к нему префикс `/api`, поэтому запросы отправляются, например, на
`http://localhost:8000/api/auth/login`.

### Подключение устройства

Если приложение запускается на физическом телефоне, `localhost` указывает на
сам телефон, а не на компьютер. Используйте IP-адрес компьютера в локальной
сети, например:

```env
EXPO_PUBLIC_BACKEND_URL=http://192.168.1.10:8000
```

Backend также должен принимать подключения из локальной сети, а firewall не
должен блокировать его порт.

## REST API, который ожидает клиент

Все endpoints вызываются с префиксом `/api` и требуют JWT, кроме регистрации и
входа.

| Метод | Endpoint | Назначение |
|---|---|---|
| `POST` | `/auth/register` | Создать пользователя |
| `POST` | `/auth/login` | Выполнить вход |
| `GET` | `/exercises` | Получить каталог упражнений |
| `GET` | `/exercises/last-sets` | Получить последние подходы пользователя |
| `GET` | `/programs` | Получить программы пользователя |
| `POST` | `/programs` | Создать программу |
| `DELETE` | `/programs/{id}` | Удалить программу |
| `POST` | `/sessions/start` | Начать тренировочную сессию |
| `GET` | `/sessions/active` | Получить активную сессию |
| `POST` | `/sessions/{id}/finish` | Завершить сессию |
| `GET` | `/sessions/{id}/sets` | Получить подходы сессии |
| `POST` | `/sessions/{id}/sets` | Добавить подход |
| `DELETE` | `/sets/{id}` | Удалить подход |
| `GET` | `/stats` | Получить статистику |
| `GET` | `/sessions/history` | Получить историю тренировок |
| `GET` | `/users/search?query=...` | Найти пользователей |
| `POST` | `/friends/request/{userId}` | Отправить заявку в друзья |
| `GET` | `/friends/requests/incoming` | Получить входящие заявки |
| `POST` | `/friends/requests/{requestId}/accept` | Принять заявку |

### Основные форматы данных

Создание программы:

```json
{
  "name": "День груди",
  "exercises": [
    {
      "exercise_id": "exercise-id",
      "exercise_name": "Жим лежа",
      "muscle_group": "Грудь",
      "target_sets": 3
    }
  ]
}
```

Добавление подхода:

```json
{
  "exercise_id": "exercise-id",
  "weight": 80,
  "reps": 8
}
```

Ответы авторизации должны иметь форму:

```json
{
  "access_token": "jwt-token",
  "user": {
    "id": "user-id",
    "email": "user@example.com",
    "username": "athlete",
    "created_at": "2026-01-01T00:00:00Z"
  }
}
```

## Состояние приложения

### `useAuthStore`

Хранит пользователя, JWT-токен и состояние загрузки. Предоставляет методы:

- `login`;
- `register`;
- `logout`;
- `checkAuth`.

### `useWorkoutStore`

Хранит упражнения, программы, активную сессию, подходы и последние результаты.
Предоставляет методы загрузки данных, создания и удаления программ, управления
сессией и подходами.

## Обновление данных

На главном экране, в списке упражнений, программах и профиле поддерживается
pull-to-refresh. При обновлении заново загружаются соответствующие данные с
backend.

## Частые проблемы

### Запросы уходят на неправильный адрес

Проверьте `EXPO_PUBLIC_BACKEND_URL` в `.env`. После изменения переменной
перезапустите Expo с очисткой кеша:

```bash
npx expo start -c
```

### На телефоне backend недоступен

Замените `localhost` на IP-адрес компьютера в локальной сети и убедитесь, что
телефон и компьютер подключены к одной сети.

### Пользователь неожиданно вышел из приложения

При ответе `401` клиент удаляет локальные данные авторизации. Проверьте срок
действия JWT и корректность backend-валидации токена.

### Не загружаются данные после входа

Убедитесь, что backend запущен, endpoint начинается с `/api`, а сервер
разрешает CORS-запросы для web-версии.
